# Park a worktree

Use the current worktree. Use the public repository, `rudoi/strudeland` on GitHub. Find its configured fetch remote with `git remote -v`. If none exists, fetch from `https://github.com/rudoi/strudeland.git` directly. Fetch only `refs/heads/main` from the matching remote or URL and resolve `FETCH_HEAD` to the base commit immediately after the fetch. In the commands below, substitute that commit for `BASE`. Never create or remove a worktree, force a branch checkout in another worktree, or delete the previous branch.

1. Inspect `git status --porcelain`, the current branch or detached HEAD, and `git rev-parse --show-toplevel`. Stop if a Git operation is already in progress. Derive `llm/{username}/{worktree-name}-parking` from the first whitespace-delimited word of `git config user.name` and the worktree root's basename, both lowercased. Validate the branch name with `git check-ref-format --branch`. Use the same name every time, with no numeric suffix. Check `git worktree list --porcelain` and stop if the parking branch is checked out elsewhere. Fetch and record the public main commit for this run as described above. Stop if any prerequisite fails.

2. If the worktree is dirty, show the status letters and paths and list the current commits from `git log --oneline BASE..HEAD`. Ask whether to preserve or discard the work. If preserving, get the user's branch name and approval for a local checkpoint commit. Create the branch at the current HEAD, stage the agreed paths, commit, and verify that the worktree is clean. Leave that preservation branch as committed and continue to the parking branch checks. If discarding, get explicit confirmation for the affected paths before clearing them. Keep ignored files and any untracked paths the user did not authorize removing. Verify a clean status before continuing. A branch creation alone does not save dirty files.

3. For a clean starting worktree or after authorized discarding, run `git -c rebase.autoStash=false rebase --empty=drop BASE` to drop commits already integrated upstream, including changes made empty by a squash merge. On conflict, capture the conflicting paths, abort this rebase, report the conflict and whether the abort succeeded, and stop. For another rebase failure, report the failure and stop. After a successful rebase, check `git log --oneline BASE..HEAD` and `git status --porcelain` again. If any work remains, show it and wait for the user's decision. On preservation, get a branch name and create it at the rebased HEAD, using the dirty-work procedure if needed. On abandonment, get explicit confirmation before proceeding. Keep the original branch if it still exists.

4. Before reusing an existing parking branch, check whether it contains commits outside the fetched main commit, even when starting on a different branch. If it would lose commits, show their hashes and subjects and get explicit confirmation to abandon them or preserve its tip under a user-named local branch first. A preservation branch already verified to contain that tip is sufficient. After any pause, recheck status, HEAD, the parking branch tip, and whether another worktree holds that branch. Review any new work before proceeding. Create the parking branch at the fetched commit if missing. Otherwise switch to it if needed and, with a clean worktree, reset it to that commit if needed.

5. Verify the current branch, that HEAD equals the fetched main commit, and that `git status --porcelain` is empty. Report the parking branch, the commit, and any preservation branches. If verification fails, report the actual state.
