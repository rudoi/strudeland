# Authored note grids

Luoyuan's flute line has ten authored onsets across eight rows. A caret on an underscore in the eighth row should open that row and show the D5 that began in the seventh. A pitch drag on that rectangle should change the D5 spelling where it was written, keep its glide duration, and reveal the changed pitch in the editor. The same note can also appear in two different voices in the arrangement. A drag on one of those voices has a different edit scope.

## Identify the producer

Extend the Acorn analysis in [source.ts](../../src/lib/piano-roll/source.ts) with a per-document index connecting an array of authored rows, its rendered pattern expression, and its lexical binding. Feed the index the existing visits, declaration identities and scope lookup. The index supplies the owning array span, pattern expression span, row and cell spans, and downstream pattern uses. Keep the row that contains the caret as a separate navigation hint. Moving between rows retains the pattern identity, even when the active hold originated outside the viewport.

Recognize the legacy consumer by matching the following straight-line statements in one lexical scope. Use a canonical Acorn subtree for the consumer with role bindings for its local identifiers. Walk against the template, recording each declaration once and checking references by lexical identity. Compare operators, order, call receivers, arguments, strings, regexes and constants. Ignore positions, grouping parentheses, comments and formatting. Use the raw spelling of string literals wherever switching quote delimiters activates Strudel mini. Permit a different error message only when its interpolation has no effects and the accepted width stays the same. This admits a renamed synthetic fixture and the actual script. A checksum of the song or variable names would fail both as soon as the author moved the music.

| Role | Required behavior |
| --- | --- |
| Rows | Immutable array binding with one unescaped, single-quoted literal per row. Check each nonempty row has 16 whitespace-separated cells for this legacy consumer. |
| Flatten | `flatMap` visits rows in order and returns each trimmed whitespace split. Its length guard throws unless the row has 16 slots. |
| Run scan | An initially empty event list, an initially unset previous pitch, and a forward scan. Each iteration counts immediately following underscores, emits one weighted pair, then advances by the count. Rest and leading hold runs emit silence and retain the previous pitch. |
| Pitched run | Split the cell on a colon. A nonempty glide with a previous pitch sets the bend to current MIDI minus previous MIDI. Otherwise the bend is 0.55. Attack is the numeric glide when present and 0.09 seconds otherwise. Use the same string for the note and the next run's previous pitch. |
| Pattern | `stepcat(...events).slow(rows.length)`. The pattern-producing initializer is the capture and fallback site for edits to the definition. |

Check the global dependencies at the relevant visits, including `stepcat`, `note`, `silence`, `noteToMidi` and `Number`. Extend the existing static-safety checks to cover reassignment or re-registration of these functions and relevant methods. Ensure intermediate arrays and their aliases have only the matched references through construction. An extra read that exports a mutable array, writes a cell, or changes event order invalidates the proof. A later musical use of the constructed pattern is expected. Keep opaque downstream uses marked incomplete in the existing use listing. A partial resemblance to a consumer confers no authority to rewrite its cells. If its pattern output is independently identifiable, inspect that expression and use the evaluated-event edit path there. An unrelated string array supplies no roll target.

For new songs provide a shared application scope function, for example `noteGrid(['c4 _ ~ g4:0.20', '_ ~ ~ ~'])`. Rows have equal positive width, and each row spans one logical cycle. Section meter supplies labels and physical beat durations. The defined grammar is an explicit-octave pitch in the existing editable MIDI range, an optional colon followed by a finite nonnegative decimal number of seconds, `_`, or `~`. A lexical suffix of `:0` is present and activates the interval rule. Keep single quotes in documented examples and round-trip them through the song formatter. Reject invalid rows in the helper with a row and cell diagnostic. Put row decoding and run projection in one pure module consumed by both the source codec and the pattern constructor. Register the same constructor through the desktop/render and host prebakes. Resolve a direct call with an inline array or an immutable, verified rows binding. Preserve the legacy idiom in existing files.

## Project the rows

Scan the original UTF-16 source slices for non-whitespace runs, retaining each cell's raw text and half-open span. Slice the pitch and suffix independently. Keep every delimiter, quote, tab, comment, and inter-cell space outside the writable spans. Flatten first, then scan. A run beginning at absolute slot `i` with length `n` occupies the exact logical interval `[i/width, (i+n)/width)`. A rest absorbs subsequent holds and the beginning of the first row can be silent. The last slot has no implicit connection to the first. Previous pitch starts unset for the constructed pattern and survives rests within it.

Project one `RollNote` per pitched run. Store the origin at the pitch substring, cell range, exact spans, and source spelling including suffix separately from the display. Use an onset-slot identity local to this grid and snapshot. A viewport beginning mid-note clips its visible interval while preserving the original edges for a drag. Carets inside pitch, suffix, hold, rest or row whitespace focus their containing row. A complete selected cell/row/array explicitly opens the same grid. Neighboring comments, the validation constant and the diagnostic message are outside the grid. Keep previous and next bars accessible with the existing page controls.

At the definition, project the authored line once and explain that its downstream voices share the edit. Collect uses from the constructed pattern binding. In the actual intro, `fluteVoice(fluteCall)` is a custom wrapper. Retain its lexical use even if the analysis cannot establish its section. At a use or in the arranged view carry both the local expression/occurrence and the optional grid definition. Use the local edit operation when a cell rewrite would affect another occurrence or layer. Explicit navigation to the definition selects the authored scope. A time-and-pitch coincidence with a sine or noise layer never proves ownership. When an arrangement mapping lacks an exact inverse, the arrangement planner owns the gesture.

## Write and validate an edit

1. Start from the original snapshot, projected runs, intended scope, source anchor, and meter-aware gesture endpoints. A pitch-only edit replaces the pitch substring using the existing spelling-style rules. Preserve suffix bytes, even for equivalent spellings such as `:0.20` and `:0.2`.
2. For move, resize, insert and delete, compute required absolute slots from exact fractions. A move preserves the note's exact logical-cycle length. At a meter change the resulting duration in beats can differ. Both logical edges must map to integral slots within the array. A moved onset takes its full original spelling and suffix. Preserve every unedited note's start and end. Consume space from silence or the original run; release vacated cells to silence. Break a rest's following underscore when leaving it would unintentionally extend the edited sound. Preserve the existing text in cells that already decode to the desired score. Fixed cells on both sides of a row boundary can be patched in this specific format.
3. Build sorted, nonoverlapping replacements for the changed cells only. Apply them in memory against the expected old text. Reparse the array and repeat consumer recognition. Check script shape with the array masked, exact untouched bytes outside the patch set, and the projected event sequence. Compare every onset, length, pitch, glide seconds and bend against an independent expected score obtained by applying the gesture then recomputing predecessor relationships. A move that changes pitch order can affect multiple neighbors' bends. Expose affected notes in the result, including an unchanged source token whose effective bend changed.
4. Return original-coordinate patches and mapped feedback anchors. The new onset is primary for a move, the pitch substring for a retune and the vacated onset for a deletion. A carry-in edit may reveal an earlier source row while the roll stays on the working bar. The session checks the revision and submits all replacements as one isolated history transaction.
5. If the proposed notation would overlap another pitched run, require a fractional slot, or extend past the finite rows, keep the requested musical operation and invoke the prepared event-edit plan at the selected pattern or song occurrence on this drop. Supply the **pattern-producing expression** for a definition edit, since the array evaluates to strings. Keep the generated entry visible and use the edited pattern projection on subsequent drags, including when focus returns to a row. Recognize that enclosing edit during source resolution and carry its capture span. Each gesture makes exactly one source transaction.

## Acceptance and independent tests

The in-memory reference probe queried the local Luoyuan producer with the vendored `stepcat`, `note`, `silence` and `noteToMidi`. Its first three relevant observations are reproducible from the source. The opening A5 occupies `[0,27/16)` with bend 0.55 and attack 0.09. G5 occupies `[27/16,2)` with bend −2 and attack 2. The final D5 occupies `[109/16,63/8)` with bend −3 and attack 0.38. Changing only the first pitch to B5 in memory changed G5's bend to −4 and left its attack and both spans fixed. The other eight complete producer events matched exactly.
